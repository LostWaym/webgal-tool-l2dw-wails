# 编辑器交互设计要点

## 维护规范

本文档默认只读。仅在用户主动维护本文档、明确要求修改时才更新；其他任务即使涉及交互设计，也只查阅，不顺带修改。

只收录跨功能可复用的设计原则，写清设计取舍，不记录具体业务规则、快捷键、控件样式或实现细节。去掉业务背景后仍有指导意义，才值得收录；已有条目能涵盖的，合并而不重复新增。

## 设计原则

- **让操作靠近对象。** 在对象所在的位置提供新增和编辑入口；能就地完成，就不另开表单。
- **降低操作精度要求，不降低结果精度。** 扩大有效操作区域，由系统将输入对齐到合法结果；只考虑用户当前要控制的维度。
- **让模式可见、可退出。** 进入模式后立刻提示当前操作，并提供就近的退出方式，不要求用户记住唯一入口。
- **区分试探与确认。** 临时预览不改变正式状态；确认后才提交，取消时恢复操作前状态，并尽量保留视口等上下文。
- **按焦点和模式分配输入。** 文本编辑时避免快捷键干扰输入；其他控件获得焦点不应无故屏蔽快捷操作。前台模式应隔离后台响应，避免一次输入产生多个结果。
- **让方向和范围可辨。** 可变换的视觉对象应明确表达其范围和方向，避免仅凭对称轮廓判断朝向。
- **按需显示，准确反馈。** 辅助信息在使用时突出显示；需要持续参考时允许保留，但应弱化以免干扰当前操作。操作前标明将影响的对象，操作后只强调实际生效的结果。
- **让选项依赖关系可见。** 仅在前置条件满足时显示相关选项；前置条件暂时失效不应丢弃已有选择。
- **保持界面和手感稳定。** 内容增减不挪动关键控件，溢出交给局部滚动；缩放不应改变用户感知到的操作容差。
- **区分内容、偏好与临时状态。** 内容随项目保存，偏好独立保存，临时状态不覆盖偏好。默认保留现有数据，覆盖或批量删除前再确认。
